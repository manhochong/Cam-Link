# Cam Link USB 實機測試步驟

## 安裝及接線

安裝 `release/CamLink-0.2.9.apk`，App 名稱是「Cam Link」。手機需 Android 10 以上及 USB Host。0.2.1 加入 Google Drive；未登入及啟用雲端時只作本機接收。帳戶設定與上傳方式見 [Google Drive 設定與使用](Google-Drive設定與使用.md)。使用者已指示暫緩 100 張測試，以下大型連拍步驟先保留作後續驗收。補掃設定、測試筆記及診斷報告均在主頁的「展開進階工具」。

電腦安裝完成後，將手機從電腦拔下，使用可靠的 USB 資料線直接連接相機。相機選 PC(Tether)，手機允許此 App 存取 USB 裝置。若另一個相機 App 正使用 USB，先關閉該 App。

若上一輪在命令或回應階段失敗：先停止測試，等相機寫卡結束，拔掉 USB 並將相機關機再開機，之後重新接線。不要在失敗後只連按「連接」；相機可能仍停留在上一個未完成交易，後續錯誤不能當作獨立測試。

確認相機仍把 JPG 寫入記憶卡，先用可正常拍攝的設定測試；App 不替你更改相機的儲存目的地或快門設定。

## 每輪測試

1. 在 App 記錄相機連拍模式、JPG 尺寸／品質、RAW＋JPG 或 JPG、卡槽、線材；先使用「每 2 秒補掃」。
2. 按「開始接收」。這時不要拍攝，避免新照片被當成卡內舊照片。
3. 等待顯示「可以拍攝」，第一輪先拍 10 張。確認手機接收到檔案，相機仍可以正常操作。
4. 按相機實體快門做 100 張／300 張活動連拍測試。記錄實際卡上張數，不能只記大概按住快門幾秒。
5. 停拍，等待相機寫卡完成，按「停拍並完成接收」。待接收及驗證中應歸零。失敗項目可在仍連接時用補掃重試。
6. 匯出最近一次診斷 ZIP，另保存這一輪記憶卡上的原始 JPG。匯出報告不包含 JPG。
7. S1M2、S1R2 必須分別執行以上步驟，不能以其中一款結果代替另一款。

有些 USB 模式只能讀卡而不能繼續拍攝。PC(Storage) 可用來診斷讀檔能力，但不能算通過本項目的聯機連拍驗收。

## 核對完整原圖和漏圖

在電腦建立一個只含「這一輪」卡上 JPG 的資料夾，例如 `C:\Projects\Cam Link\test-data\S1M2-round1-card`。保留卡檔原樣；不要混入建立基線前的舊照片，也不要把雙卡備份當作新增的不同拍攝。

```powershell
python tools/compare_card.py --report "報告.zip" --card-directory "這一輪的卡檔資料夾" --expected-count 100 --out "比對結果.json"
```

工具逐檔計算 SHA-256、大小及相同內容出現次數。`PASS_BYTE_MATCH` 代表指定卡檔集合與手機成功清單的位元組與數量一致；不代表其他輪次或其他相機通過，也不代表拍攝沒有變慢。相同張數但內容不同、同名不同內容、缺檔、多檔、不完整 session 都會失敗。

若電腦沒有 PATH 中的 Python，可改用本機已安裝的 Python 完整路徑。

## 測試拍攝是否變慢

固定同一張卡、曝光、對焦模式、連拍速度、影像品質和拍攝場景，保持電池與溫度相近。

先不接 USB，連拍固定 10 秒，記錄卡上新增 JPG 數與寫入指示結束時間。再接 USB 並啟動 App 接收，重做相同測試。交替執行至少 3 組；比較中位數。工程目標為拍攝張數下降不超過 5%、緩衝恢復時間增加不超過 10%，並且觀景器／按鍵沒有明顯停頓。

|---|---|---|---|---|---|---|---|
| S1M2 | 1 | 待測 | 待測 | 待測 | 待測 | 待測 | 待測 |

## 如何解讀速度

USB MB/s：成功檔案總大小除以其 GetObject 傳輸總時間。全程 MB/s 包含等待拍攝、掃描與驗證。發現至驗證秒數從手機發現照片物件開始，不是快門到手機時間。尚無相機硬體觸發時間同步，不可混用 EXIF 與手機時鐘聲稱低快門延遲。

## 斷線或不支援時

匯出報告中的 device.json、events.log、files.csv、summary.json 可供分析。若標準 PTP 無法取得相機新照片，需要依實際能力與封包調整 Panasonic 支援。不要不停切換 USB 模式繼續同一輪測試；停止後重新建立基線，將結果分開。

重新連接相機會建立新的 session。斷線期間及上一輪缺圖不會自動補回，必須由卡上原檔比對與另行補傳處理。App 顯示成功的 JPG 已通過大小／結構及 hash 計算，但結構檢查本身不能證明所有壓縮資料正確，仍需卡檔比對。

0.1.4 會保留主 JPEG 結尾後的附加資料，CSV 的 `trailing_bytes` 記錄其大小；SHA-256 包括整個檔案，不會裁掉尾端。0.1.3 的 `Unexpected bytes after JPEG EOI` 不一定代表照片損壞，可用電腦端複驗器檢查原先保留的 `.part`，不要直接刪除。結束測試時請按「停拍並完成接收」，待完成再拔線，避免 session 被記成非正常停止。

手機 JPG 位於 App 顯示的 `Android/data/hk.camlink.usb/files/sessions/<session>/jpg`；新版 Android 的一般檔案管理器可能無法存取此路徑，可用已授權電腦 ADB 備份：

```powershell
adb pull /sdcard/Android/data/hk.camlink.usb/files/sessions ./phone-sessions
```

移除 App 會刪除手機暫存，請先備份；不會刪除相機卡上原檔。
