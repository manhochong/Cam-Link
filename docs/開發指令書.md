# Cam Link USB 接收測試版開發指令書

日期：2026-10-31（香港時間）　版本：0.1

## 2026-10-31 第二階段授權與規格（取代下文階段閘門）

使用者指示先不測 100 張，繼續完成程式，Google 帳戶使用 manhochong。故立即開發 Google Drive；下文「USB 驗收後才加入 Drive」只保留為原始計畫，不再阻擋開發。現有 DC-S1 十張接收成功不能代表 S1M2／S1R2 或長連拍驗收。

版本 0.2.0：保留 USB 讀取與診斷，加入 Google 官方 AuthorizationClient（drive.file scope）、手機 Google 帳戶選擇、顯示實際登入帳戶、建立／選擇本 App 可存取的 Drive 資料夾、明確啟用自動上傳、Wi-Fi 限制／流動網絡選項、暫停／繼續、最近一輪手動加入、逐檔佇列與錯誤狀態。帳號不得由暱稱推測完整 email，登入由使用者選 manhochong 的實際 Google 帳戶。

每張完成本地驗證的 JPG 才排入 SQLite 持久佇列；每項固定綁定帳號、目的資料夾及本機檔案。切換帳號或資料夾不得挪用舊佇列。捕捉 session 記下上傳目的地，重啟可補入 rename 後尚未排隊的完整 JPG。舊測試照片不自動上傳，需手動加入最近一輪。

上傳使用預先產生並持久保存的 Drive file ID，避免回應遺失時重試製造副本。resumable session URI 只存 App 私有資料庫；以伺服器 Range 恢復，不假設已送出即已接收。4 MiB 分塊串流，網絡中斷保留狀態，退避重試；401 要重新授權，權限／容量等永久失敗清楚列出。上傳完成後再讀 Drive metadata，比對 size、MD5，若提供 SHA-256 一併比對；任何失敗不可列為已驗證。原始 JPG 不壓縮、不自動刪除手機或相機照片。

USB、驗證及雲端上傳分別執行；預設單條上傳連線，先避免壓垮手機儲存及網絡。前景 dataSync 服務處理 Android 時限，遇系統終止後保留佇列，回到 App 按繼續即可恢復。開機不偷偷啟動前景服務，不承諾系統強制停止後仍持續傳送。

Google Cloud OAuth 登記是外部設定前提：啟用 Drive API、設定測試使用者、登記 Android package 和安裝簽章 SHA-1。程式不內嵌 client secret，不向使用者索取密碼／token，不使用其他 App 的 OAuth 身份。使用者已要求先完成程式並提供設定步驟；未設定前，真實登入與雲端上傳驗收標示未完成。

測試覆蓋：斷點 Range、斷線後查詢、完成回應遺失、預配置 ID 去重、過期 session、認證／權限／限流、checksum 不符、帳號綁定、程序重啟持久性、暫停／繼續與離線。安裝保持同 package 和簽章、保留歷史照片。交付 APK、原始碼、建置方式、OAuth 設定、操作及驗證紀錄。

參考：[Google Android 授權](https://developer.android.com/identity/authorization)、[Drive resumable upload 與預配置 ID](https://developers.google.com/workspace/drive/api/guides/manage-uploads)、[Drive scope](https://developers.google.com/workspace/drive/api/guides/api-specific-auth)、[Android 前景服務時限](https://developer.android.com/develop/background-work/services/fgs/timeout)。

目標是在 Android 手機以 USB 連接 LUMIX DC-S1M2、DC-S1RM2，在相機實體快門連拍後接收完整 JPG，量測速度、核對漏圖，並以接線／不接線基線比較拍攝影響。第一階段不接 Google Drive。

## 已確認事實及工程邊界

- 兩款相機官方文件均提供 PC(Tether) 聯機拍攝與存圖功能，但文件描述 Windows／macOS，不能據此宣稱 Android 已相容。
- 官方公開 LUMIX SDK 是 Windows DLL，目前頁面未列出這兩款；本版不能直接引用為 Android 驅動。
- 使用 Android USB Host API，自行實作小範圍標準 PTP 接收與診斷。先驗證相機提供的標準讀取操作；若需 Panasonic 私有握手／事件，記錄實際 capability 與錯誤後再開發，不猜測會修改相機設定的指令。
- PC(Storage) 成功讀檔不代表可以邊拍邊傳；驗收必須在可正常拍照的模式完成。
- 本版只讀取相機資料，不刪除、格式化、控制快門或改變儲存目的地。確認相機仍寫卡後才做連拍驗收。

## 第一版功能

1. 繁體中文單頁介面，顯示 USB 裝置、連線狀態、階段、成功／失敗／待驗證數、接收 MB/s、延遲與檔案目錄。
2. USB 權限申請、Panasonic 裝置與介面列舉、前景 connectedDevice 服務、接線／拔線／停止處理。未知介面不得盲目發送 PTP。
3. GetDeviceInfo、OpenSession、GetStorageIDs、GetObjectHandles、GetObjectInfo、GetObject、CloseSession。所有命令由單一 USB 執行緒序列化；驗證 transaction ID、容器型別、長度與回應碼。USB I/O 有逾時；失去同步後停止 session，不能盲目重送。
4. 開始時建立卡內現有 handle 基線，完成前不可拍攝；只抓取其後新增 JPG。事件提示快速加入佇列，定期掃描補足未收到的事件；不在拍攝中遍歷讀取每張舊照片 metadata。
5. 每個 session 內同 handle 去重，Camera Busy 暫緩重試；失敗清楚保留並可手動補掃。停止前先停拍，再補掃與排空，檢查未完成佇列。
6. 檔案串流落地到 .part，完成 USB 回應、位元組數核對、落盤、JPEG 結構檢查與 SHA-256 後才列入成功；不以 GetThumb、縮圖或重壓縮冒充原 JPG。全圖不載入記憶體。
7. USB 下載與本地驗證分工；驗證佇列有界，儲存不足時停止收圖並提示。傳輸中斷不把半檔當成功。重連建立新 session，明示上次缺圖需卡檔核對／補傳，不能聲稱自動跨 session 補全。
8. 本地報告含裝置 descriptor、相機型號／韌體（若相機提供）、操作／事件清單、每張原檔名／handle／大小／SHA-256／發現與開始結束時間／來源／重試、事件紀錄、錯誤和 session 摘要。
9. 匯出診斷 ZIP（不含照片），供離線核對。附電腦端工具，以單次測試記憶卡 JPG 與成功接收 manifest 比較 SHA-256 多重集合；同名、跨資料夾同名、雙卡重複均不可只用檔名判斷。
10. 不加網絡權限、不接 Google Drive、不加入即時取景，避免混入無關流量與負載。

## 量測定義

- USB 接收時間：GetObject 發送前至成功回應，另記落盤與驗證時間。
- 接收吞吐量：檔案實收 bytes ÷ GetObject 耗時；另外報告 session 整體有效吞吐量，不能只展示最高單張數值。
- 發現到完成：主機發現 handle 至完整驗證完成。不是按快門到手機的延遲；相機 EXIF 時鐘不可直接與手機單調時鐘相減。
- 結構檢查不等於逐像素解碼正確；與卡上原 JPG 的 SHA-256 完全一致才是位元組完整性的主要驗收依據。
- 無漏圖判斷必須依據獨立卡檔集合，或使用者提供的精確預期張數；成功下載數與事件數相同不足以證明無漏圖。

## 實機驗收矩陣

兩款機身各自記錄韌體、手機型號／Android、USB 線材、記憶卡、JPG 尺寸／品質、RAW＋JPG／JPG、卡槽與連拍模式。初版一次只接一部相機。

1. 單張 10 張：取得完整原 JPG，卡端與接收端 SHA-256 相同。
2. 每輪 100 張及 300 張連拍，各至少 3 輪；短促連拍與長連拍分開測。包括實際使用的機械／電子快門及 SH（如可用）；不假設全部模式均支援 tether。
3. 斷網不影響本版；USB 拔線、相機關機、螢幕關閉、切換 App、低剩餘空間等情況不能誤報完成。
4. 速度比較：相同相機設定，先不接 USB 拍攝固定 10 秒，再接 USB 接收拍攝固定 10 秒；以記憶卡實際張數、緩衝清空時間和觀景器／按鍵反應比較，至少 3 組交替測試。
5. 拍攝影響門檻先採中位數有效連拍張數下降不超過 5%，緩衝恢復時間增加不超過 10%；這是工程驗收目標，不是已證實結果。超出或樣本不足列為待調整。
6. 零漏圖、零多傳、零 hash 不符、零成功列中的半檔；任何一款未測，該款相容性維持「未驗證」。

## 實作和交付次序

先完成本指令書，再建置 Android 專案與可安裝 APK。依序測試 PTP 封包／部分讀取／回應錯誤、JPEG 損壞與截斷、去重重試、報告核對工具。安裝可用的已授權手機，驗證啟動與未接相機流程。兩款相機接線與連拍測試需使用者實際拍攝，保留逐輪報告。

交付：APK、完整原始碼、可重複建置腳本、測試結果、操作說明和比對工具。版本標示 USB 技術驗證版，不標示正式相容或性能保證。USB 接收驗收通過才加入 Google Drive。
